# Apex Seoul 고착 자동 복귀·전체/차량별 기록 검토안

갱신일: 2026-09-13
상태: 2026-09-13 1차 코드 반영·자동 검증 완료. 아래 검토 계약과 실제 구현 범위는 마지막 구현 현황에서 구분한다. 실행 순서는 [다음 구현 우선순위](./apex-seoul-next-priority-plan.md), 저장 계약은 [로컬 저장 설계](./apex-seoul-local-save-plan.md)를 따른다.

## 현재 확인과 결정 방향

사용자 제보: 코너에 박히면 전진·후진 입력으로도 탈출하지 못해 주행이 끝까지 막히는 경우가 있다. 이번 정적 확인만으로 충돌 원인을 재현하거나 확정한 것은 아니다. 충돌 해소 로직을 점검하면서, 계속 플레이할 수 있도록 고착 자동 복귀를 추가한다.

현재 `RecordsScene`은 세 차량의 PB·완주 횟수와 선택 차량의 최근 5개를 표시한다. 전체 차량 통합 목록과 목록 모드 전환은 없다. `TimeAttackScene`의 checkpoint 알림은 누적 통과 시간만 표시하고 `GameplayHudState`에는 PB split이 없다.

채택 제안은 다음과 같다.

- 충돌 후 입력해도 움직이지 못하면 짧은 안내·깜박임과 함께 도로 중앙으로 복귀한다.
- Records는 `전체 / 차량별` 탭을 사용자가 번갈아 선택한다. 읽는 중 목록이 바뀌는 자동 순환은 MVP에서 제외한다.
- 체크포인트와 결승 통과 시 `전체 PB / 차량 PB` 대비 시간 차이를 함께 표시한다. 이니셜 D에서 연상한 통과 시점 비교 경험을 적용하는 제안이며 특정 작품의 실제 UI 사양을 재현한다는 의미는 아니다.

## 고착 판정과 복귀 계약

정상 정차·제동·저속 코너링을 오인하지 않도록 속도 하나로 판정하지 않는다. 활성 주행 중 전진 또는 후진을 시도하고, 가드레일/노변 충돌 접촉이 지속되며, 실제 차량 위치 변화가 미미한 상태가 연속될 때 후보로 본다. 엔진 회전이나 최고 도달 progress가 아닌 실제 종·횡방향 이동을 측정한다. 접촉이 짧게 끊기는 경우에는 작은 유예를 두되 의미 있는 이동 또는 입력 해제 시 누적을 해제한다.

초기 튜닝안은 고착 3초 후 복귀, 복귀 직전 0.5초 안내, 배치 후 1.5초 동안 차량 alpha를 완만하게 변화시키는 것이다. 안내 중 스스로 탈출하면 취소한다. 이동 임계값·접촉 유예는 게임의 실제 world 단위와 세 차량 저속 주행을 측정해 확정한다. countdown·pause·blur·finish에서는 판정과 복귀를 실행하지 않으며 숨겨진 탭의 경과 시간을 누적하지 않는다.

복귀 위치는 현재 종방향 위치의 도로 중앙을 우선한다. 장애물이나 충돌 경계와 겹치면 같은 위치 이하의 가장 가까운 안전한 중앙 지점으로 후퇴한다. 전방 checkpoint나 finish 너머로 이동하지 않는다. 차량을 도로 접선 방향에 맞추고 종·횡속도, yaw/slip, 가드레일 contact/bounce, 충돌 잠금과 표시 상태를 일관되게 초기화한다. 엔진·기어도 정지 상태와 맞춰 순간 가속이나 잔여 충돌이 발생하지 않도록 한다.

깜박이는 동안에도 운전은 가능하고 정상 충돌 판정은 유지한다. 깜박임을 무적 시간으로 사용하면 코너를 관통할 수 있으므로 MVP는 안전 배치와 충돌 상태 해제로 해결한다. 발동 중 재진입을 막고, 복귀 후 새 관찰 구간부터 다시 판정한다. reduced motion에서는 고정 반투명 차량과 `도로로 복귀` 안내로 대체하며 전체 화면을 점멸하지 않는다.

주행 시간은 고착 대기·안내·복귀 후 연출 동안 계속 흐른다. 별도 시간 벌점은 추가하지 않는다. 복귀 이동은 checkpoint 통과/finish 이벤트나 진행률 증가를 발생시키지 않으며, 이미 통과한 checkpoint를 다시 집계하지 않는다. retry·씬 종료 시 판정 timer와 시각 효과를 해제한다.

기록 정책 제안: 정상 복귀를 사용한 완주도 PB 대상에 포함한다. 앞으로 이동하지 않고 시간 손실이 유지되는 것을 검증해야 한다. `RunSummary`에 `recoveryCount`를 저장해 결과·이력에 표시하고, 과거 데이터의 누락값은 0으로 읽는다. 이 필드의 schema 호환 처리를 명시적으로 추가한다. 복귀 도입은 주행 조건 변경이므로 `rulesetVersion`을 올리고 이전 규칙 기록을 현재 비교에서 제외한다. 단축·checkpoint 건너뛰기 방지가 확인되기 전에는 이 정책의 구현 완료를 선언하지 않는다.

## Records 전체/차량별 전환 (이전 검토안)

후속 리뷰와 코드 반영으로 이 절의 탭 설계는 대체되었다. 현재 Records는 최근 완주순 차량/시간/이름 단일 목록이다. 최신 계약과 경기 종료 후 세 글자 이름 입력 TODO는 [로컬 저장 설계](./apex-seoul-local-save-plan.md)의 Records 단순화 항목을 따른다. 주행 중 전체/차량별 split 계약은 계속 유지한다.

`전체`는 선택한 코스·현재 ruleset의 **이 브라우저에 저장된 모든 차량 기록**이다. 온라인 전체 랭킹을 뜻하지 않는다. `차량별`은 같은 조건에서 선택 차량만 필터한다. 기본 탭은 전체이며 차량별 탭은 마지막으로 선택한 차량을 사용한다. 코스를 바꿔도 탭을 유지한다.

두 탭 모두 상단에 해당 범위의 PB와 완주 횟수, 아래에 `베스트 / 최근` 목록 선택을 둔다. 전체 베스트는 차량별 PB를 시간순으로 정렬하고 차량명을 필수 표시한다. 차량별 베스트는 해당 차량 PB를 표시한다. 최근 목록은 저장된 최근 이력을 완주 시각 역순으로 합치거나 필터하며 페이지당 5개로 탐색한다. 전체 통합 목록에서는 `runId`로 중복을 제거한다. 동률 순서는 완주 시각과 runId로 고정한다.

기존 보관 계약인 차량 bucket별 최근 20개와 별도 PB를 유지한다. 전체 최근은 이 보관분의 합집합이며 무제한 전체 이력이 아니다. UI에 보관 범위를 명시한다. 누적 완주 횟수는 bucket 집계를 합산하고 화면에 남은 최근 이력 개수로 계산하지 않는다. 빈 차량/코스에는 `기록 없음`을 표시한다. legacy·이전 규칙·내장 목표는 개인 PB 목록에 섞지 않는다.

탭과 목록 선택은 터치/클릭 및 키보드로 조작 가능하게 하고 선택 상태와 조작 안내를 표시한다. 기존 코스·차량 방향키와 충돌하지 않도록 모드 전환 키는 별도로 정한다. 자동 순환은 필요성이 확인되면 유휴 메뉴 연출로만 재검토한다.

## 체크포인트·결승의 두 기준 비교

주행 시작 시 같은 코스·ruleset에서 `overallBestRun`과 `vehicleBestRun`을 snapshot으로 고정한다. 전체 PB는 모든 차량의 bestRun 중 완주 시간이 가장 빠른 **하나의 실제 run**이다. 구간마다 다른 차량의 최소 시간을 가져오지 않는다. 차량 PB 역시 하나의 실제 run이며, 저장 갱신 후에도 이번 비교 기준은 바꾸지 않는다.

checkpoint i의 delta는 `현재 누적 통과 시간 − 기준 run의 checkpointTimesSec[i]`이다. 음수는 앞섬, 양수는 뒤처짐이며 부호·문구를 함께 표시해 색상만으로 구별하지 않는다. 표시 반올림은 계산 후 수행한다. 최초 주행 또는 기준 checkpoint가 없으면 `-- / 비교 기록 없음`으로 표시하며 0초로 대체하지 않는다.

예시: `CP 2 · 전체 PB (Mirae) +1.24초 / 차량 PB (Raven) −0.38초`. 전체 PB와 차량 PB가 같은 run이어도 두 라벨을 유지해 의미를 일관되게 한다. 주행 중 알림은 초기안 3초간 두 줄로 표시하고 도로 중앙 시야를 가리지 않는다. 기존 1.25초 알림 시간은 두 값을 읽을 수 있도록 조정한다. 화면이 좁으면 상단 전용 영역에 두 줄을 배치한다. 다음 checkpoint/finish 알림이 오면 이전 알림을 교체한다.

통과 후 HUD는 `LAST SPLIT`으로 표시한다. 동일 위치 timestamp/ghost가 없는 상태에서 실시간 차이처럼 계속 갱신하지 않는다. 결승에서는 주행 전 snapshot의 finishTimeSec와 비교하고 `전체 NEW BEST / 차량 NEW BEST / 첫 기록`을 각각 판정한다. 전체 기록이 있어도 현재 차량 기록이 없을 수 있다. 동률은 NEW BEST가 아니다. 결과 상세의 개별 구간 차이는 누적 checkpoint 차분으로 계산하고 누적 split과 구분한다.

시간 경계 보간·pause/focus 보호(P0-4)를 먼저 확보한다. 전체 PB는 기존 bucket에서 파생해 별도 저장하지 않으며, 결과/HUD/Records가 같은 선택 함수를 사용한다.

## 구현 대상과 확인 기준

| 영역 | 제안 변경 |
| --- | --- |
| 고착 복귀 | `TimeAttackScene`, `playerVehicleController.ts`와 충돌 상태 소유 모듈. 판정·안전 위치 선택은 순수 함수로 분리하고 scene이 배치/연출 연결 |
| 진행·시간 | `courseRun.ts`와 주행 session. 복귀 이동과 실제 이동을 구분하고 checkpoint 중복·건너뛰기 방지 |
| 저장·비교 | `runRecord.ts`, 저장 schema/validator, 전체/차량 PB snapshot 선택 함수, recoveryCount 호환 처리 |
| 화면 | `recordsScene.ts`, `gameplayHudState.ts`, `gameplayHud.ts`, `resultScene.ts`, checkpoint 알림 |

검증은 구현 시 수행하며 이번 문서 수정에서 PASS로 간주하지 않는다.

- 세 차량의 좌·우 급코너 충돌에서 전진/후진 탈출 실패를 재현하고 복귀 후 양방향 입력과 조향이 정상인지 확인한다.
- 정상 정차, 브레이크 유지, 저속 회전, 실제 후진 탈출, 짧은 접촉, 입력 해제에서는 오발동하지 않는다.
- pause/blur/countdown/finish/retry에서 timer 누적·늦은 복귀·효과 잔류가 없다. 30/60/120fps에서 동일 조건의 판정 시간이 일치한다.
- checkpoint/finish 직전 복귀와 여러 번 복귀에서도 거리 이득·중복 통과·시간 정지·충돌 관통이 없다.
- 전체 PB가 다른 차량인 경우, 같은 run인 경우, 현재 차량 무기록, 완전 무기록, 동률, 과거 ruleset, checkpoint 누락에서 목록과 두 delta가 일치한다.
- PB가 최근 20개에서 밀려나도 전체 PB와 split 비교에 남는다. 저장 실패와 기록 초기화 후에는 기존 저장 상태 정책을 따른다.
- 터치·키보드 목록 전환, 페이지 경계, 작은 화면의 두 줄 split, reduced motion 복귀 표현을 실제 화면에서 확인한다.

## 2026-09-13 구현 현황

- `stuckRecovery.ts`: 활성 주행에서 브레이크를 누르지 않은 가속 입력과 가드레일 접촉을 관찰한다. 기준 위치에서 종·횡 이동이 12 world units 이하인 상태 3초 + 안내 0.5초 후 복귀하며 접촉 유예는 0.2초다. 실제 후진 기능은 기존 컨트롤에 없으므로 추가하지 않았고, 기존 가속 입력에 연결했다. 브레이크만 유지하거나 가속과 브레이크를 함께 누르는 의도적 정차는 발동시키지 않는다.
- `TimeAttackScene`: 현재 Z를 그대로 유지한 채 lateralOffset 0과 정지 차량 기본 상태로 복귀한다. 현재 코스의 충돌은 도로 양옆 가드레일이므로 중앙에 배치할 수 있다. 중앙 장애물을 추가하는 코스에서는 안전 위치 검색을 먼저 확장해야 한다. 충돌·drift·launch·표시 상태를 초기화하고 기존 충돌 횟수는 보존한다. 1.5초 alpha 연출 중 입력·충돌 판정은 유지하며 OS reduced motion에서는 고정 alpha를 사용한다.
- 복귀 중 시간·기존 checkpoint를 유지하고 recoveryCount를 저장한다. schema v1에 호환 가능한 선택 필드를 추가했으며 누락은 0, 음수/비정수는 거부한다. 주행 규칙은 `time-attack-v2`로 변경했다. 이전 bucket/PB는 보존하고 현재 목록·비교에서 제외한다.
- Records에 전체/차량별 탭, 베스트/최근 모드, 페이지당 5개 탐색, 차량명·색상·복귀 횟수, 보관 범위 안내를 연결했다. Tab으로 범위, B로 목록, 방향키로 코스/차량, PgUp/PgDn으로 페이지를 바꾸며 클릭/터치 조작도 제공한다.
- `runComparison.ts`의 공통 선택/표시 함수를 사용해 주행 시작의 전체·차량 PB snapshot을 고정한다. 상단 LAST SPLIT과 결승·결과 화면에 두 기준의 누적 차이를 표시하며 최초/동률/기록 없음도 분리한다. 결과 checkpoint 행은 누적 비교이고 개별 구간 차분·개선 팁은 P2 후속이다.
- checkpoint/finish 통과 시간에 프레임 경계 보간을 적용했다. blur/숨김 중 주행과 고착 timer를 정지하고 입력을 해제하며 복귀 첫 프레임의 큰 delta를 제외한다. 별도 수동 pause 메뉴와 countdown 잔여 프레임 정밀화까지 P0-4 전체 완료로 선언하지 않는다.

검증: `qa:recovery-records`, `qa:recovery-records-browser`, `qa:local-save`, `qa:local-save-browser`, `qa:gameplay-hud`, `qa:guardrail-collision`, `build` PASS. 신규 순수 검증은 30/60/120fps 고착 시간·오발동 방지·checkpoint 시간 보간·PB 보존·snapshot·복귀 횟수 저장을 확인했다. 격리 브라우저 fixture로 실제 scene 복귀, 복귀 후 controller 가속, 전후 위치·시간·checkpoint 보존, Records 탭/페이지, LAST SPLIT/결과, retry와 focus 정지를 검증했다. Records·작은 Records 화면·복귀·split·결과 캡처를 확인했다. 사용자 제보의 코너 고착을 세 차량 모두 실제 운전으로 재현한 검증은 아니며 12 units/3초 기준은 주행 피드백에 따라 조정할 수 있다.
