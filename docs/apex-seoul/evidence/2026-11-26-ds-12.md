## 기준과 선행

## 구현

- [엔진 합성기](../../../games/apex-seoul/src/game/platform/engineAudio.ts)는 [합성 실험](../../../games/apex-seoul/src/engine-sound-lab.ts)의 차량별 engine/exhaust waveform, cylinder pulse divisor, lowpass 및 bandpass noise 방식을 가져온다. 재현 가능한 spool noise를 생성하고 gain/frequency에 25–40ms smoothing을 적용한다.
- Raven NA에는 engine/exhaust oscillator 2개, Mirae single에는 spool 1개, Seorin twin에는 독립 primary/secondary spool 2개를 구성한다. boost는 실제 drivetrain 출력값을 읽는다.
- [주행 화면](../../../games/apex-seoul/src/game/timeAttackScene.ts)은 시작·countdown에 idle snapshot을 전달하고 controller update 직후 실제 RPM, throttle, shift cut, fuel cut, boost snapshot을 전달한다. 합성기는 snapshot을 읽어 frequency/gain을 계산한다.
- [runtime adapter](../../../games/apex-seoul/src/game/platform/runtimeAudio.ts)는 unlock 전 snapshot을 복사해 보존하고 backend 생성 시 적용한다. 기존 SFX/master bus와 mute/pause를 사용한다. finish/retry/destroy 시 oscillator와 noise source를 stop/disconnect하고 filter/gain 및 context를 정리한다. retry는 이전 snapshot을 비운다.
- 이번 후보는 지속음의 load 감소로 lift·shift를 표현한다. DS-13 사건 소비와 one-shot은 후속 카드가 담당한다.

## 청음 후보와 판정

실제 production 합성기를 OfflineAudioContext로 렌더링한 mono 22050 Hz, PCM16, 8초 WAV다. 공통 입력은 0–1초 idle, 1–4초 가속, 4–5초 shift cut, 5–6초 lift, 6–7초 mute, 7–8초 idle 복귀다. 가속 구간은 900–6500 RPM과 실제 합성 API의 boost 입력을 사용한 고정 청음 시나리오다. 차량별 실제 주행 기록은 위 browser fixture에서 따로 확인했다.

| 후보 | 자동 peak | mute 구간 peak | 청음 결과 |
| --- | --- | --- | --- |
| [Raven NA](./2026-11-26-ds-12-audio/raven.wav) | 0.290266 | 0 | 사용자 승인 대기 |
| [Mirae single](./2026-11-26-ds-12-audio/mirae.wav) | 0.422056 | 0 | 사용자 승인 대기 |
| [Seorin twin](./2026-11-26-ds-12-audio/seorin.wav) | 0.328202 | 0 | 사용자 승인 대기 |

세 차량 각각 아래 항목을 확인한다.

- idle에서 소리가 안정적으로 이어지는가
- 가속 중 RPM 상승과 음높이 변화가 자연스러운가
- Raven의 엔진음, Mirae spool, Seorin 두 단계 spool을 구별할 수 있는가
- shift/lift 전환에 과한 클릭·충격·거슬리는 고역이 없는가
- 차량 간 볼륨 차이와 지속 청취 피로도를 수용할 수 있는가
- mute와 idle 복귀가 기대대로 들리는가

자동 검사에서 clipping 임계값 1 미만과 mute 무음을 확인했다. 음색·차량 식별·전환 품질의 사람 판정은 요청한 상태다. DS-12 최종 완료 승인은 이 청음 결과를 받은 뒤 갱신한다.
