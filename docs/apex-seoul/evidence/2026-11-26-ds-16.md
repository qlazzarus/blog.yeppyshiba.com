# DS-16 핵심 QA 자동화 검증

검증일은 2026-11-26 KST다. 선행 DS-00과 DS-10의 완료 기록 및 실제 검사 스크립트를 확인했다.

## 현재 상태

**2026-11-26 사용자 지시에 따라 DS-16 완료를 가정한다.** 로컬 자동 검증은 통과했다. 실제 CI 실행과 배포 QA 단계 복원은 미검증이며, 아래 내용은 당시 관측 결과다.

작업 시작 시 기존 변경을 포함한 작업 트리를 확인했다. 진행 중 HEAD가 `ce097ea39afd111435d0f2ba165170a715078cb5`에서 `b8f2d1b0a537b2b1d1ddc8a58288d334b7550643`으로 변경됐고, 새 커밋에는 이번 작업의 `qa:ci`와 배포 QA 단계가 포함됐다. 이후 현재 작업 트리에서 배포 QA 단계의 삭제를 확인해 사용자에게 복원 여부를 질의했다. 당시 YAML에는 gate가 없어 배포 중단 완료 조건을 보류했다. 후속 사용자 지시에 따라 계획상의 상태를 완료 가정으로 갱신했다.

## 구현과 검증 대상

- [게임 package.json](../../../games/apex-seoul/package.json)의 `qa:ci`가 기존 16개 검사를 `&&`로 순차 실행한다. 첫 실패의 종료 코드를 반환한다.
- [배포 workflow](../../../.github/workflows/deploy.yaml)의 검증 대상 구성은 `npm ci` 직후, analytics 조회와 build 전에 `npm run qa:ci --workspace @games/apex-seoul`을 실행한다. 실패 허용 옵션이 없고 deploy job은 build 성공에 의존한다. 이 구성은 클린 복사본에서 검증했다.
- [출처 검사](../../../games/apex-seoul/scripts/audit-asset-attributions.ts)에 `optimizeDeps.noDiscovery`와 빈 `include`를 지정했다. SSR manifest 로딩 중 불필요한 client dependency scan이 server 종료와 경합하던 오류 출력을 해결했다. 기존 출처·누락·금지 라이선스 assertion을 모두 실행한다.

`qa:ci` 실행 순서는 다음과 같다.

```text

qa:adapter-boundaries
qa:pseudo3d-core

qa:vehicle-handling-balance

```

선정 기준은 DS-00에서 검증한 회귀와 완료된 입력·PWA·출처 계약이다. 물리 관련 검사는 현재 상수로 실행했다. 출처 검사는 생성 명령보다 먼저 실행하므로 저장된 고지와 코드가 어긋나면 실패한다.

## 실행 환경과 결과

- Linux 호스트의 Node.js `v24.12.0`, npm `11.18.0`을 사용했다. sandbox에는 Node/npm이 없어 호스트 실행 권한으로 검증했다.
- 클린 복사본은 `/tmp/vscode-agent-codex-sandbox-SUt3Ra/apex-ds16-ef8dh6u_`에 만들었다. 루트 package/lock/config, game workspace와 workflow를 복사하고 의존성이 없는 상태에서 설치했다. 검사 수정 후 동일 파일을 복사해 최종 재검증했다.

## 브라우저 자동 검증의 실행 전제

브라우저 suite에는 Playwright Chromium과 Linux 브라우저 시스템 라이브러리, 실행 중인 Vite 개발 서버가 필요하다. [기존 런타임 브라우저 검사](../../../games/apex-seoul/scripts/audit-runtime-qa-browser.mjs)는 기본 Windows Edge 경로를 사용하므로 Linux에서는 환경 변수를 명시한다. 서버는 QA URL을 지원하는 개발 모드로 실행한다.

저장소 루트에서 브라우저를 준비한다.

```sh
npx playwright install --with-deps chromium
```

첫 번째 터미널에서 개발 서버를 유지한다.

```sh
npm run dev --workspace @games/apex-seoul -- --host 127.0.0.1 --port 5194 --strictPort
```

두 번째 터미널에서 기존 자동 검사를 실행한다.

```sh
APEX_SEOUL_QA_BROWSER=chromium APEX_SEOUL_QA_BASE_URL=http://127.0.0.1:5194/game-assets/apex-seoul/ npm run qa:runtime-qa-browser --workspace @games/apex-seoul
```

다른 browser fixture의 URL 변수와 시작 조건은 [DS-00 환경 근거](./2026-11-24-ds-00.md)를 따른다. DS-17은 실제 기기·설치·센서·오디오 및 통합 pointer flow 판정을 담당한다.
