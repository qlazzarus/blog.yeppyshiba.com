## 변경과 DS-08 인계 API

- [RunRecordStore](../../../games/apex-seoul/src/game/platform/runRecord.ts)의 `updateRunName(runId, value)`는 ASCII 영문 정확히 세 글자를 대문자로 정규화한다. 공백·개행·숫자·전각·길이 오류는 `invalid-name`으로 거부한다.
- 현재 ruleset의 허용된 차량·코스에서 해당 runId가 들어 있는 bucket 한 개를 찾고, 일치하는 recent/PB의 이름을 갱신한다. 중복 ID가 여러 bucket에 걸쳐 있거나 run이 없으면 `excluded`를 반환한다. 오래된 ruleset과 제외 run도 갱신 대상에서 제외한다.
- PB가 recent에서 밀려난 경우에도 PB의 runId로 갱신할 수 있다. 반복 호출 시 완주 count/time·checkpoint·다른 run의 이름이 유지된다.
- profile v1에 `lastPlayerName`을 호환 필드로 저장하고 `getLastPlayerName()`으로 읽는다. 필드가 없거나 잘못된 값이면 `PLAYER`를 반환한다. `saveSetup()`은 마지막 이름을 함께 보존한다.
- 반환값은 `{ recordStatus, profileStatus }`다. 이름 거부·기록 차단 시 profileStatus는 null이다. 두 저장 문서의 성공·실패를 독립적으로 알려 주며 한쪽 쓰기가 실패해도 메모리 갱신과 성공한 쓰기는 유지한다. 같은 runId·이름으로 재시도하면 count/time을 추가하지 않고 저장을 재시도한다.
- 미지원 version 문서를 덮어쓰지 않고 storage 거부 시 memory-only 정책을 따른다. 기록의 외부 변경은 갱신을 차단한다. profile 외부 변경은 profile 쓰기를 차단해 다른 탭의 마지막 이름을 덮어쓰지 않게 한다.
- [결과 payload](../../../games/apex-seoul/src/game/resultScene.ts)의 선택 필드 `recordRunId`에 [주행 화면](../../../games/apex-seoul/src/game/timeAttackScene.ts)이 수락된 완주의 ID를 전달한다. `saved`와 `memory-only`가 대상이며 excluded·미지원 버전·외부 변경에서는 undefined다. 기존 fixture payload와의 호환성을 위해 선택 필드로 추가했다.

DS-08은 결과의 `recordRunId`와 위 API를 사용하고 두 저장 결과를 확인해 이름 저장 상태를 안내하면 된다. 이번 작업 범위는 저장·payload 계약이다.
